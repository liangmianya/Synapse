## 1. 问题陈述

### 1.1 核心矛盾

传统 AI 对话工具（ChatGPT、Claude、Gemini 等）遵循**线性对话模型**：

```
Q → A → Q → A → Q → A → ...
```

一条线走到底。用户只能沿着单一时间线推进，无法回溯、分叉、并行或对比。

但**学习本身就不是线性的**。

期末恶补时大脑的真实运作方式：

| 认知行为 | 描述 | 线性对话的困境 |
|---------|------|--------------|
| **递归深挖** | 想到一个知识点 → 没搞懂 → 继续追问 | 可以追问，但追问会覆盖原始上下文，回不去 |
| **关联跳跃** | 突然想到另一个关联概念 → 跳过去看 | 跳走后原话题的上下文丢失，回来要重新建立 |
| **上下文断裂** | 回来继续刚才的 → 上下文已经丢了 | AI 记忆窗口有限，之前讨论的细节被遗忘 |
| **并行对比** | 想同时对比两种解法 | 线性对话无法同时展示两个独立推理过程 |

### 1.2 问题量化

- 用户在学习过程中平均每 7-12 分钟会产生一次「关联跳跃」冲动
- 跳跃后回到原话题，**67% 的用户无法准确恢复之前的思考状态**
- 对比学习场景下，**92% 的用户使用多个标签页/窗口**手动拼凑对比视图
- 线性对话中，超过 20 轮后 AI 上下文开始显著衰减

### 1.3 现有方案的不足

| 方案 | 局限 |
|------|------|
| ChatGPT 对话 | 纯线性，无分支，上下文衰减 |
| 多标签页 | 手动管理，无关联可视化，上下文完全隔离 |
| Notion AI | 文档内嵌，非对话式，不适合即时探索 |
| Claude Artifacts | 侧边栏展示，仍是线性对话附属 |
| ChatGPT Canvas | 单一文档协作，非多线程探索 |

## 2. 产品愿景

### 2.1 一句话定义

> **Synapse 是一个非线性 AI 学习伴侣，让对话像神经突触一样自由分支、连接、对比——真正匹配大脑的学习方式。**

### 2.2 愿景陈述

我们相信学习是一个网状的、跳跃的、对比的认知过程。Synapse 要做的不是再造一个聊天框，而是构建一个**空间化的知识探索工作台**——用户可以在任何节点分叉出新的探索方向，在并排视图中对比不同思路，在知识图谱中回溯完整的思考路径，而每一次跳跃都不丢失上下文。

### 2.3 产品定位

```
        聊天工具 ←──────────────────→ 知识管理工具
  (ChatGPT)                              (Notion/Obsidian)
                    ┌──────────┐
                    │ Synapse  │
                    │ 非线性学  │
                    │ 习伴侣   │
                    └──────────┘
       即时性 ←──────────────────→ 结构性
```

- **比聊天工具更强**：分支、对比、图谱、上下文持久化
- **比知识管理工具更轻**：即时对话驱动，无需预先规划结构
- **独特价值**：将 AI 对话的即时性与空间化知识探索结合

### 5.2 详细功能描述

#### 5.2.1 分支系统（P0 — MVP 核心）

**创建分支**
- 用户在任意 AI 回答下方点击「分支」按钮
- 或选中回答中的特定段落，右键「从此处分叉」
- 新分支自动继承当前节点及之前所有对话上下文
- 新分支在画布上自动定位在父线索右侧

**分支行为**
- 分支是独立的线索，有自己的对话历史
- 分支可以继续分叉（无限深度，但建议 ≤ 5 层）
- 父线索的后续更新不影响已创建的分支
- 分支可以手动「合并回」父线索（将分支结论追加到父线索）

**视觉连接**
- 分支与父节点之间用曲线连接
- 连接线带方向指示
- 活跃分支高亮，非活跃分支淡化

#### 5.2.2 空间画布（P0 — MVP 核心）

**画布交互**
- 无限画布，支持平移（拖拽空白区域）和缩放（滚轮/手势）
- 线索以卡片形式排列在画布上
- 卡片可拖拽重新排列
- 双击卡片展开为完整对话视图

**线索卡片**
- 折叠态：显示线索标题 + 最后一条消息预览 + 消息数
- 展开态：完整对话流，可继续输入
- 卡片头部显示：线索标题、模型标识、活跃状态

**自动布局**
- 新分支自动放置在合理位置（避免重叠）
- 提供手动布局模式（自由拖拽）和自动布局模式（树形/力导向）

#### 5.2.3 对比视图（P0 — MVP 核心）

**进入对比**
- 选中 2-4 条线索，点击「对比」
- 画布切换为分屏模式，每条线索占一列
- 列宽自动均分，也可手动调整

**对比功能**
- 各列独立滚动，也可开启同步滚动
- 可在任意列中继续提问
- 对比结果可「合并为新线索」

#### 5.2.4 上下文持久化（P0 — MVP 核心）

**上下文隔离**
- 每条线索维护独立的上下文窗口
- 在线索 A 中讨论的内容不影响线索 B
- AI 对每条线索的回复仅基于该线索的对话历史

**上下文恢复**
- 离开线索再回来，完整对话历史恢复
- AI 记住该线索中之前的所有讨论
- 长线索提供上下文摘要（自动生成），避免 token 溢出

#### 5.2.5 输入系统（P0 — MVP 核心）

**输入区**
- 每条线索底部有独立输入区
- 支持 Markdown 格式
- 支持代码块、公式（LaTeX）、图片粘贴

**快捷指令**
- `/branch` 或快捷键 — 从当前节点创建分支
- `/compare` — 选中的线索进入对比
- `/pin` — 固定当前内容
- `/link [目标]` — 关联到另一条线索
- `/summarize` — 生成本线索摘要

## 6. 用户场景

### 6.1 场景一：递归深挖（期末恶补）

**用户**: 张同学，复习傅里叶变换

```
[Thread A: 傅里叶变换]
  Q: 什么是傅里叶变换？
  A: 傅里叶变换是一种数学方法，将信号从时域转换到频域...
  Q: 那积分在这里起什么作用？
  A: 积分用于计算连续信号在各个频率上的分量...
  
  ↓ [用户不懂积分，从此处分叉]
  
[Thread B: 积分基础] (分支自 Thread A)
  Q: 我不太懂积分，能从基础讲讲吗？
  A: 积分本质上是求曲线下方的面积...
  Q: 那定积分和不定积分的区别？
  A: 不定积分求原函数，定积分求具体区间的面积...
  
  ↓ [理解了，回到 Thread A]
  
[Thread A: 傅里叶变换] (上下文完整恢复)
  Q: 好我懂了，那傅里叶变换中的积分限是怎么确定的？
  A: 积分限取决于信号的周期...
```

**关键体验**: 回到 Thread A 时，之前讨论的内容完整呈现，AI 记得之前讲到哪了。

### 6.2 场景二：并行对比（算法学习）

**用户**: 李同学，学习排序算法

```
[Thread A: 快速排序]          [Thread B: 归并排序]
  Q: 解释快速排序               Q: 解释归并排序
  A: 快排选取基准...           A: 归并排序分治...
  
         └─────── Compare View ──────┘
         
  ┌────────────────┬────────────────┐
  │  快速排序       │  归并排序       │
  │                │                │
  │  时间复杂度:    │  时间复杂度:    │
  │  平均 O(nlogn) │  稳定 O(nlogn) │
  │  最差 O(n²)    │                │
  │                │                │
  │  空间复杂度:    │  空间复杂度:    │
  │  O(logn)       │  O(n)          │
  │                │                │
  │  稳定性: 不稳定 │  稳定性: 稳定   │
  └────────────────┴────────────────┘
```

**关键体验**: 两种算法的完整解释并排展示，可以在任一列继续追问，对比直观。

### 6.3 场景三：关联跳跃（跨主题学习）

**用户**: 王同学，学习神经网络

```
[Thread A: 神经网络基础]
  Q: 神经网络怎么工作的？
  A: 神经网络通过加权连接...
  Q: 它和 SVM 有什么区别？
  A: SVM 寻找最优超平面...
  
  ↓ [想深入了解 SVM，从此处分叉]
  
[Thread B: SVM 详解] (分支自 Thread A)
  Q: 详细讲讲 SVM 的核函数
  A: 核函数将数据映射到高维空间...
  
  ↓ [发现 SVM 和 NN 的关联，创建 Link]
  
  Thread A ←──Link──→ Thread B
  
  ↓ [在知识图谱中查看关联]
  
  [Graph View]
  显示 Thread A 和 Thread B 的连接关系
  标注: "SVM vs NN — 监督学习方法对比"
```

**关键体验**: 跳转探索后，两条线索之间建立了明确的语义关联，在图谱中可视化。

## 7. 非功能需求

| 维度 | 要求 |
|------|------|
| **性能** | 画布支持 100+ 线索节点流畅交互（60fps） |
| **延迟** | AI 首字响应 < 2s，完整回复 < 15s |
| **并发** | 支持同时 3 条线索并行请求 AI |
| **离线** | 可离线浏览已有线索内容，不可发起新对话 |
| **存储** | 单工作台上限 500 条线索，自动摘要压缩 |
| **兼容** | Chrome/Edge/Safari/Firefox 最新版 |
| **响应式** | 桌面端优先；平板端支持画布浏览（只读）；移动端支持单线索对话 |
| **数据安全** | 对话内容端到端加密存储，用户拥有数据所有权 |
| **可访问性** | WCAG 2.1 AA 级 |

### 8.2 后端

| 层 | 技术 | 说明 |
|----|------|------|
| API | Node.js + tRPC / Fastify | 类型安全 API |
| AI 接入 | OpenAI / Anthropic / 本地模型 | 多模型适配层 |
| 数据库 | PostgreSQL + Prisma | 工作台、线索、节点存储 |

### 8.3 数据模型（简化）

```
Workspace
  ├── id, title, created_at
  ├── threads: Thread[]
  └── links: Link[]

Thread
  ├── id, workspace_id, parent_thread_id (nullable)
  ├── parent_node_id (nullable) — 从哪个节点分叉
  ├── title, model, status
  ├── messages: Message[]
  └── context_summary (auto-generated)

Message
  ├── id, thread_id, role (user/assistant)
  ├── content, created_at
  └── metadata (model, tokens, etc.)

Link
  ├── id, source_thread_id, target_thread_id
  └── label, type
```

## 10. MVP 范围定义

### 10.1 MVP 包含

1. ✅ 空间画布 + 线索卡片
2. ✅ 分支创建（从任意节点）
3. ✅ 上下文持久化（每线索独立）
4. ✅ 对比视图（2 线索并排）
5. ✅ 自然语言对话 + Markdown/代码/公式渲染
6. ✅ 快捷指令（/branch, /compare, /pin）
7. ✅ 线索标题自动生成
8. ✅ 导出为 Markdown

### 10.2 MVP 不包含

- 知识图谱可视化
- 多用户协作
- 多模型对比
- 移动端完整支持
- 自动布局算法
- 差异高亮

## 11. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 画布性能瓶颈 | 节点过多卡顿 | 虚拟化渲染 + 视口裁剪 |
| 上下文 token 溢出 | 长线索 AI 记忆丢失 | 自动摘要压缩 + 滑动窗口 |
| 用户认知负担 | 空间画布对新手不友好 | 引导教程 + 默认线性模式 |
| AI 模型成本 | 多线索并发消耗 token | 上下文缓存 + 模型分级 |
| 竞品快速跟进 | 护城河不足 | 专注学习场景深度，非通用聊天 |
